## Root cause
1. The Export page displayed only a subprocess exit code without identifying the exact export file, format or last completed run.
2. The Validation and Export Validate pages had logs and metrics/preview state but neither an always-visible, **run-bound** model/source summary nor a verified output-opening action. `[save-dir]` is emitted before inference completes, so showing it as successful as soon as it appears would be misleading.
3. A result with process exit code 0 could still lack output files or a required TFLite deployment manifest. The UI needed explicit **Running / Stopping / Succeeded / Failed / Cancelled** states and a proof-of-existence gate.

## Known limits and next steps
- Source model file presence can be reported, but R42 does **not** snapshot/hash model input weights at task start, because that could synchronously hash huge models on the GUI thread. It labels the captured model reference and whether a nonempty file exists **now**, never claims the bytes were pinned throughout a run. User edits to the path field mid-run cannot relabel previously reported metrics.
- A CLI-reported `[save-dir]`/artifact path can exist before work is complete, so exported/predicted output success requires **exit code 0 and verification at finish**. Validation with real reported metrics may complete successfully without a saved plot folder, but Open Location remains disabled. A failed or cancelled run can still leave partial files; these are marked unconfirmed, not deleted, and Open Location remains disabled. Empty validation metrics are **Unknown** rather than guessed as zero; validation can succeed with either real reported metrics or verified output, and exported validation follows the same rule.
- A TFLite export with an absent, mismatched or unreadable U27 YOLO sidecar cannot be confirmed in the result panel. Old sidecar-free models may still be selected for validation under existing compatibility rules; R42 does not alter those backend rules.
- Output verification checks for nonempty artifacts and manifests; it is not an integrity proof for every exported format or model quality. OS `Open Location` may fail on systems without an associated file manager; a warning is displayed, not a claim of opening.
- R42 limits new UI to a scrollable 150px-high detail area within existing Status groups. It does not widen Marking, alter preview panel stretch, change class mappings, reset saved UI splitter sizes, rewrite YOLO labels or touch any other component.
- Release gate on Windows: `cd CustomTrainer && python -m unittest discover -s tests -p 'test_task_result_r42.py' -v`; `python -m unittest discover -s tests -v`; use real `.pt` validation, exported `.tflite/.onnx` validation, successful/failed/stopped exports, source input edits while running, disappeared/deleted outputs, and `Open Location` for file/folder. Verify R41 undo/redo, compact Marking pane, Quick Deploy selected/current and U25 cache leases after packaging. Merge only after review and explicit authorization.
