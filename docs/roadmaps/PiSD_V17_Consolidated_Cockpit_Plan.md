### V17-M2 — Driving authority and safety (depends M1)
Define backend-acknowledged state model and atomic authority transitions. Automatic readiness is a request only after normal authorization/preflight and existing interlocks; never auto-clear latched STOP or replace required explicit safety rearm, never bypass existing enable/consent policies. If automatic readiness conflicts with current backend authorization, stop and obtain owner decision rather than weaken protection. No mode-selection actuator command except neutral/stop where necessary; wait for backend confirmation; disable ambiguous controls while pending. Selecting AI is standby; Start AI explicitly requests authority; Stop AI cancels authority and leaves neutral human control; joystick/keyboard intervention first cancels AI, confirms neutral and ownership, then accepts fresh human input. Do not replay buffered/held input or automatically resume. Preview inference must never issue motor commands, mutate training labels or compete for lease. Preserve global Space STOP, pointer capture/cancel, touch, keyup, visibility/blur, navigation/unload, watchdog heartbeat/timeout, network faults and stale frames. Distinguish intended, accepted, applied, unknown feedback; no fake stopped/readiness display on missing ACK. Camera/model faults block unsafe control; explicit recovery and fresh command required; backend enforces zero independently of browser. Settings pauses driving before displaying form; reopening cannot restart AI. Preserve existing preflight/STOP/rearm/error diagnostics and hardware ownership. Gate: real virtual service readback, race/failure/late response tests, no unintended movement on entry, switch, reload, close or recovery.

### V17-M3 — Capture and data workflow (depends M1/M2)

Keep capture independent of motor STOP when services healthy; handle camera/network interruption using existing recovery semantics (do not falsely claim file saved). Preserve frame/label formats, metadata, timestamps, storage paths, model manifests, recorded calibration, source of actual motor command versus independent AI prediction. Preserve manual correction/assist data semantics; remove only redundant Assisted UI mode, maintain advanced correction access if still required by existing workflow. Saved data list, type filter, metadata, download ZIP, confirmed deletion; preserve recovery and filename/path security. Do not create new record formats or change trainer ingestion without explicit compatibility qualification. Gate: real synthetic recordings/captures, ZIP contents, trainer import and failure/restart recovery; confirm recording remains coherent across supported mode transitions.

### V17-M6 — Experimental physical overlay (independent after M5)
Implement separately selectable, versioned opt-in renderer only after approval to implement. Legacy remains default; production physical promotion is a separate gate. One preview with engine selector; no dual windows. Camera controls: height, pitch, horizontal FOV, forward offset, optical centre Y. No visible optical centre X control (centre default; calibrated intrinsic can retain measured cx internally). Vehicle: wheel track, corridor width, turn correction. Prediction: maximum speed, lookahead time, opacity. No visible unit suffixes; document canonical units, coordinate conventions and accessible descriptions/help to avoid ambiguity. Defaults from prototype are illustrations only, not actual measurements: 22 cm, 10 degrees, 80 degrees, 10 cm, cy 50%, track 20 cm, corridor 18 cm, correction 1, speed .8 m/s, horizon 2 s, opacity 85%. Do not overwrite existing values. Right panel live side diagram camera mount/height/pitch/vertical FOV, top diagram horizontal FOV/track/trajectory/corridor, image diagram optical centre/horizon. Auto-select appropriate diagram on focusing parameter, allow manual tabs. Illustrate actual selected parameter and geometry, not arbitrary shapes.

Physical model (flat ground, positive-right convention):
- For measured left/right wheel velocities vL,vR, track b: v=(vL+vR)/2, omega=(vL-vR)/b. For constant velocity, x(t)=v/omega*(1-cos(omega*t)), z(t)=v/omega*sin(omega*t); continuous straight limit x=0,z=v*t. Offsets use local normals before projecting; constant physical width. Calibrate command-to-wheel-speed model separately; PWM is not measured velocity. Use actual motor_service mapping including direction, per-wheel limit/bias, minimum inside speed, optional pivot and arcade mode; do not assume prototype's ideal nonpivot default covers all configs. Handle stationary/pivot, reverse, tight turns and footprint degeneracy explicitly (hide unsupported corridor or show labelled centre-only); provisional 90-degree preview cap requires validation.
- Camera height h, downward pitch theta, forward offset a: Yc=h*cos(theta)-(z-a)*sin(theta); Zc=h*sin(theta)+(z-a)*cos(theta); u=cx+fx*x/Zc; image_y=cy+fy*Yc/Zc. Horizon cy-fy*tan(theta) fixed for fixed pose, not throttle. Near-plane clipping then natural image-boundary clipping. Derive focal length from calibrated intrinsics or FOV; use actual frame dimensions/crop and distortion/rectification consistently. Prototype assumes zero roll/yaw, centered mount and square pixels; calibrated extension must explicitly support or reject unsupported conditions. No claim of collision avoidance or precise swept footprint.
- References for later source verification: OpenCV calib3d camera model (https://docs.opencv.org/4.x/d9/d0c/group__calib3d.html), Zhang, A Flexible New Technique for Camera Calibration (IEEE TPAMI 2000, DOI 10.1109/34.888718), ROS 2 Control wheeled mobile robot kinematics (https://control.ros.org/master/doc/ros2_controllers/doc/mobile_robot_kinematics.html). These are engineering references, not measured PiSD validation.
- Gate: analytical straight/left/right symmetry, horizon invariance, finite depth clipping, sign parity, extreme settings/no NaN, camera resolution/aspect/ROI mapping, repeatability and unit conversion tests. Compare matched measured ground reference points and held-out supervised trajectories to legacy on same camera/commands; report pixel and ground error distributions, sample counts, uncertainty, failures, latency/resource costs. Define measurement protocol and owner-approved thresholds BEFORE evaluation; no invented passing thresholds or fabricated hardware evidence. Until qualification, label experimental and reversible; no influence on motor commands/AI model/training labels.
