## Batch 4 — piTrainer realistic nonzero minimum workspace ratios

[b379138](https://github.com/henrywork059/PiDrive/commit/b379138744b952a6203c2f6a29c458e3b6a59ea1) implements **piTrainer 0.11.18**. The previous R50 save/restore test used zero soft minimums, whereas actual Data/Validate/Train three-panel presets use 260/300/300px or 260/320/300px minimums. The existing responsive resize algorithm added these minimum widths first and then distributed the remaining pixels using proportions already measured from the **entire pane**, distorting otherwise feasible user-saved proportions. For example, at a 1200px three-panel workspace with 50/25/25 proportions and 260/300/300 minimums, the old calculation generated approximately 430/385/385px rather than the feasible intended 600/300/300px. The targeted change allocates preferred full-pane proportions, freezes only panes below their soft minima, then distributes the leftover width among unfrozen panes in the original ratio. Exact available pixel total is preserved with integer remainder rounding. Below-minimum fallback, existing hard widget minimums, named splitters and QSettings keys, data and other components are unchanged.
