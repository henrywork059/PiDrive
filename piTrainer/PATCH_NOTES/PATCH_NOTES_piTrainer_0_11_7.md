## Root cause
The existing Train history held in-memory epoch curves, while the saved model sidecar described only deployment compatibility (model checksum, input/output contract and training seed). It did not identify which actual dataset rows/source sessions, split and preprocessing recipe produced the trained model. Restarting the trainer lost run comparisons, and historical models had no trustworthy training-run association. R40 adds separate local experiment JSON records rather than overloading deployment compatibility metadata or introducing a database.

## Compatibility, limits and release gate
- Experiment sidecars are **informational provenance** and not cryptographically signed. A verified U27 manifest SHA-256 binds the sidecar to the bytes of the named model; this does not authenticate the identity of whoever authored experiment metadata.
- `identity_label_sha256` includes effective train/validation row fields and labels, not image bytes; `preprocessing_sha256` hashes the applied recipe settings only. They are not claims that the source recordings are still present or unchanged.
- With Keras EarlyStopping `restore_best_weights=True`, the final epoch's reported `val_loss` may not reflect the final model's restored weights. Best and final validation losses are separately labelled; separate post-training Keras/TFLite validation results are **not** merged into the R40 run summary in this first iteration.
- Missing historical model sidecars, absent session fields, missing preprocess recipe or absent validation metric are displayed as **Unknown**, never a fabricated value or zero. An export from an untracked model remains valid without an experiment sidecar; existing deployment compatibility checks remain authoritative.
- A failure publishing a model's R40 experiment sidecar is surfaced as a save/export task error even when model bytes and U27 manifest may already be present. These files may require manual review/cleanup; the code does not delete existing accepted models or source recordings.
- Run summaries are stored in the working folder used when the training job started. A save/export folder can differ from the source working folder; the additional artifact sidecar carries its complete run snapshot.
- The Train Compare tab adds one new output tab **after** the existing History and Log tabs. No changes to docking, Data read-only record table, synthetic-frame rules, keyboard navigation, validation/edit navigation, preview caching, JSONL atomic writers or any other monorepo component.
