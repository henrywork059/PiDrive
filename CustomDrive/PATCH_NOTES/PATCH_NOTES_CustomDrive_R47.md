# CustomDrive GUI 0_3_18 / Mission 1 0_5_28 — R47 failure tracing

## User request
Implement roadmap **R47 — Request tracing and errors** across the **two real CustomDrive Flask web applications**. Correlate a failed Drive Apply, AI Deploy, Mission Start, saved config or arm pose action to one bounded log entry using a server-generated identifier. UI must display short error guidance with expandable safe metadata; diagnostics must not newly expose credentials, absolute/explicit file paths, raw request bodies or stack traces. Preserve accepted R43/R44/R45/R46 state and separate GUI/Mission 1 layouts.

## Root cause
The two web apps returned JSON failure status/message but no common request identifier in their process logs. Browser users could see a server exception or path as the message without a safe reference for debugging. Some rejected API operations return HTTP 200 with JSON `ok:false` or persistence `saved:false`; assuming success from HTTP status alone would mask failed Apply/Deploy/Start. A shared code import from PiServer would couple two independently maintained components, risking rollback.

## Exact files changed and behavior
1. **New** `custom_drive/request_trace.py`: shared *within CustomDrive* by both web runtimes. Registers failure-only Flask `after_request` hook for POST/PUT/PATCH/DELETE under `/api/`; detects HTTP >=400, JSON `ok:false` or `saved:false` even if HTTP 200. Adds cryptographically random server-issued **16-hex `correlation_id`**, sanitized server-defined `operation`, `X-Correlation-ID`. Preserve original HTTP status, JSON keys (including `config`/`status` if already present) and successful responses. Unexpected HTML 500 is replaced with generic safe JSON under the same HTTP status. Logs one `api_mutation_failure id=... operation=... http_status=... code=...` warning per failed mutation, with **no request data, headers, tokens, filesystem paths, exception representation or arbitrary client ID**. Sanitizes error message and nested error diagnostics; strips credentials, path assignments, URL strings, absolute paths, sensitive keys/tracebacks and overlong/deep values.
2. `custom_drive/gui_control_app.py`: install hook into actual general GUI Flask app before routes; bump **APP_VERSION 0_3_18**. **No** motor control, preview, servo or model backend behavior changed.
3. `custom_drive/mission1_session_app.py`: install same hook into **independent** Mission 1 Flask app; bump **APP_VERSION 0_5_28** only. R44 trigger zero, unsaved/saved consistency, existing motor/servo state and config remain exactly as before.
4. `custom_drive/gui_web/static/app.js`: reusable `tracedRequestError` and `appendRequestTrace` helpers wrap HTTP/JSON failure errors; `saved:false` counts only for mutations to avoid GET false positives. GUI Drive Apply and AI Deploy display short, action-specific text plus a collapsible `<details>` containing **only** validated ID, operation, HTTP code and existing safe code. No user-provided paths, model file contents, tokens or raw error exceptions are shown in new detail UI. Existing backend settings-feedback state, Drive Apply ordering, Deploy/Stop and R43 polling remain intact.
5. `custom_drive/mission1_web/static/app.js`: same error/trace UI functions for Mission 1 Save, Start, model upload/select and arm role. The standalone model upload path now checks both HTTP error **and** `data.ok:false`. The existing `saveConfig` effective-versus-saved trigger readback must succeed before mission start or servo load; this guard is **not** removed.
6. **New** `tests/test_request_trace_r47.py`: **15 stdlib** hardware-free response-hook tests using a mocked Flask request/app/response, covering success, GET, HTTP 200 fails, paths, credentials, one safe log line and ID validation.
7. **New** `tests/test_request_trace_ui_r47.cjs`: **10 Node** browser script/DOM tests covering GUI/Mission safe details, rejects injected IDs, Drive Apply/Deploy, Save/Start/Arm failure messaging, R43 polling and R44 trigger safety.
8. `README.md`: operator trace reference lookup, tests and privacy scope.
9. `PATCH_NOTES/PATCH_NOTES_CustomDrive_R47.md`: this note.

## Known limits and test gate
- New trace metadata does not rewrite ordinary successful config/model payloads or existing server state. It is not a wholesale redaction of every previous API surface; **newly emitted trace diagnostics and failure `message`/`error` fields** are sanitized. The existing read-only status payload remains the source of truth.
- UI displays a trace only for server-returned failures with a validated 16-hex ID; network loss before server receipt has no ID and uses the current offline guidance. Raw backend exceptions are intentionally not exposed in the details.
- On actual checkout run `python -m unittest discover -s CustomDrive/tests -p 'test_request_trace_r47.py' -v` and `node --test CustomDrive/tests/test_request_trace_ui_r47.cjs`, plus R33/R35/R36/R43/R44/R45/R46 regression suites. Test GUI failed Motor Apply and AI Deploy, Mission 1 failed Save, rejected Start (including missing arm/model), 401/403/500 and HTTP-200/ok:false, state readback after successful save, real E-stop/motor/servo safety, phone preview and R43 status intervals. Correlate actual UI reference to precisely one bounded log line.
