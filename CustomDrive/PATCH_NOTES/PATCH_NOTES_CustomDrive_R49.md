## Root cause
CustomDrive's Mission 1 internally maintains a bounded debug timeline with raw text and extra details, but those may contain route text, selected models, coordinates, absolute paths or exceptions and are not appropriate for copying into support reports without cleaning. The general GUI has no comparable concise, copyable event view. Directly logging every manual motor POST would also flood memory and make emergency STOP events disappear.

## Changed files and exact behavior
1. **New** `custom_drive/recent_events.py`: component-owned, lock-protected **`deque(maxlen=128)`**, copied snapshot of at most 80 entries. Five fixed fields per entry: `timestamp_utc` (UTC ISO), allowlisted `operation`, `category`, constant `title`, and `succeeded`/`failed`/`partial`/`observed`. Unknown strings normalize to constant `other`; no arbitrary value is stored. Response observer uses only **server-defined Flask endpoint names**, not client URLs, request bodies or response messages. Catches HTTP >=400, `ok:false` (including HTTP 200), `saved:false` (partial), and separates `safety_stop` from an explicit rearm. **No request-body serialization or cloud/persistent log**.
2. `custom_drive/gui_control_app.py`: add fixed route allowlist to record user-driven Camera Preview, Motor Apply, Runtime Save, AI Upload/Delete/Deploy/Stop/Config, arm action, and Emergency STOP (excludes high-frequency `/api/control` POST), with startup event. **GET `/api/recent-events`** returns only safe bounded entries. Advance GUI marker `0_3_20`. Existing PiServer-derived services, motor/servo actuation, R47 trace, R48 preflight, R44 readback, R43 polling, STOP handlers unchanged.
3. `custom_drive/mission1_session_app.py`: own independent 128-entry ring on Mission1 context before any `_record` calls. `_record` still appends the original **bounded 250 legacy raw timeline entries exactly as before**, then adds a **separate generic** transition only for known `mission/route/session/camera/model/arm` types; no raw message, route, model name, pose or fields copied. A response hook adds operator Start/STOP, rearm, Save, Model Select/Upload and Arm Load outcomes; distinct `mission_stop` safety category. New **GET `/api/recent-events`** does not call `status_payload()` or run the mission. Advance marker `0_5_30`. Latched STOP and Save-before-Start logic untouched.
4. **New** `custom_drive/gui_web/static/recent_events.js` and `custom_drive/mission1_web/static/recent_events.js`: no background polling, only on opening collapsed panel or explicit Refresh GET. `textContent` creates visible safe rows, Copy button calls Clipboard API with manual-select fallback, no POST/localStorage/settings or external telemetry.
5. `custom_drive/gui_web/templates/index.html` and `mission1_web/templates/index.html`: collapsed, accessible `<details>` adjacent to each existing R48 preflight, preserving status metrics, camera preview, motor/arm/mission controls, R45 style preferences and R44 overlay geometry. Versioned script links.
6. **New** `tests/test_recent_events_r49.py`: **16** Python hardware-free ring/response tests for cap/immutability, START/STOP/rearm outcomes, rejected/partial saves, unknown labels, zero secret leakage and GET exclusion.
7. **New** `tests/test_recent_events_gui_ui_r49.cjs` and `test_recent_events_mission_ui_r49.cjs`: **8 each** browser source/DOM/fetch tests for read-only on-demand behavior, Copy, explicit safety STOP, hidden default, offline state and no HTML injection.
8. `CustomDrive/README.md`: operator workflow and tests.
9. This `CustomDrive/PATCH_NOTES/PATCH_NOTES_CustomDrive_R49.md`.
