# CustomDrive Mission 1 0_5_25 — R44 Grip / Drop-off Trigger Legibility

## Request summary
Implement `docs/roadmaps/PiDrive_Refinement_Roadmap.md` R44: add a clear **0 / 50 / 100%** scale and live numeric **Grip** and **Drop-off** trigger labels beside the existing Mission 1 camera preview markers. Preserve the accepted U24 convention (**100% = top of frame, 0% = bottom**) and independent grip/drop-off thresholds. Editing one field should move the corresponding preview marker, while the server's effective values remain explicitly distinct until the Save response confirms them.

## Root causes
1. U24 added separate grip/drop-off frame-position thresholds and the current web overlay already drew green Grip and amber Drop-off horizontal guide lines, but lacked any **100/50/0 ruler**. The values were written only on the image and far away in Status, with no readable key directly below the preview.
2. Mission 1 backend normalization already accepts `0.0`, but both runtime `_pickup_trigger_y_px` and `_dropoff_trigger_y_px` used `...get(..., 0.3) or 0.3`. That silently replaced the **valid 0%** threshold with the **30% default** when executing the real gate, contradicting the browser overlay and saved configuration. This fix is essential for R44 acceptance, not a new trigger-direction policy.
3. The browser form used `value || 30`, discarding an explicit `0` before save. Its whole-percent rounding could also mislabel an already-valid `0.335` saved fraction as 34%, while the backend uses 33.5% and the web SVG can render precise fractional heights.
4. Previously the Mission Start and Load Arm Role handlers called `saveConfig()` but continued with physical actions even if config saving failed, because `saveConfig` swallowed the error and returned nothing. A preview marker shown at a draft value should not be mistaken for the server-applied threshold.
